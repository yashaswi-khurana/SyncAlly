## Acceptance evidence

| Requirement | Evidence |
| --- | --- |
| Fake client and separate Sandbox adapter/worker | Provider-neutral invoice port, stateful fake, HTTP adapter and separate CLI. Runtime dependency includes httpx. |
| Saved intent and committed agreement | Worker fixture commits through the existing bilateral agreement path, persists intent/outbox through #34, then explicitly authorizes seller issuance. Changed commitments, parties, recipients, inactive seller and cancelled deal are rejected. |
| Separate create/send | Normal fake call sequence is create → GET draft → send → GET status. Unknown-create recovery saves the discovered provider ID before a later send. |
| Stable operation identity | Same UUID-derived create ID across transient retry; separate saved send ID. Request snapshot/hash survives restarts. |
| Timeout/crash recovery | Tests simulate create/send timeouts both before and after mutation, plus crashes after successful provider effects. Unknown creation searches before further work; empty search never recreates. |
| Bounded retries/manual action | Permanent errors stop immediately. Unresolved creation exhausts its budget and blocks replacement; persisted backoff prevents immediate retry. Recovery guide describes controlled operator review. |
| No HTTP inside a transaction | SQLAlchemy transaction listeners assert zero active transactions on every fake provider call. Real PostgreSQL test pauses inside HTTP and confirms another worker cannot create. |
| Concurrency and stale workers | Real PostgreSQL verifies SKIP LOCKED, rollback release, exclusive live claims, expired-claim reconciliation and stale-result fencing. |
| Authoritative status | Sending acknowledgment alone cannot mark SENT; GET evidence is required. Wrong amount/currency/reference/recipient and unknown statuses stop issuance. This worker never marks PAID. |
| Secret safety | Fixed Sandbox origin, SecretStr credentials, no credentials in persisted snapshot, sanitized provider failure codes, no raw response exceptions, invalid CLI configuration errors are redacted. All tests use dummy values. |

## Reproduce

From `backend/`, with the dev dependencies installed:

```sh
python -m unittest discover -s tests -v
python -m ruff check src tests
git diff --check
```

For the PostgreSQL checks, point `TEST_POSTGRES_URL` at an isolated **test**
database whose user can create/drop schemas, then run the same unittest command.
Each concurrency fixture creates and removes its own uniquely named schema.
Without that variable, four PostgreSQL checks intentionally skip.

## Limits and outstanding gates

possible defects. Real PayPal Sandbox issuance and settlement were **not** run.
No live keys were read or used. #34 is closed; #30–#32 and Stage 6's exit check
remain required before integration. #33 must align the authenticated seller
issuance/state contract; #36 owns webhook verification and settlement updates.

payment authorization.
